# Contributing

Thank you for improving PatchPilot.

1. Open an issue or discussion for substantial behavior or boundary changes.
2. Create a focused branch and keep commits coherent.
3. Add tests for success and denial paths.
4. Run the verification commands in [the development guide](docs/development.md).
5. Complete the pull-request template with real results and residual risks.

Never include credentials, private repository content, fabricated results, copied agent prompts, or
code without compatible provenance. Security controls should fail closed. Changes that widen
command, filesystem, network, Git, or publication permissions require explicit explanation and
dedicated tests.

repository.
